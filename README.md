# DOPA ARENA

three.js 製の 3DアクションRPG（アリーナ型ハクスラ）。
**3D描画 × レベル上げ × ガチャ** の3軸で「装備を引く → 強くなる → 上の敵に挑む」を回す収集・育成ゲーム。

> **全7フェーズ完了。** 設計の全文は **[docs/PHASE0_DESIGN.md](docs/PHASE0_DESIGN.md)** を参照。

---

## 特徴（完成時）

- **外部通信ゼロ**：three.js を含む全アセットをローカル同梱。CDN不使用。
- **完全オフライン**：PWA（manifest + Service Worker）でインストール後はネット不要。
- **課金要素なし**：ガチャ通貨はプレイ報酬のみ。排出確率はデータで公開・改変可能。
- **60fps 死守**：InstancedMesh + オブジェクトプールで、敵200体でもフレームを落とさない。
- **スマホ/PC 両対応**：仮想スティック＋オートエイム / WASD＋マウス。

## 実装済みの範囲

拠点で強化し、ガチャを引き、装備を整え、ステージに挑み、ボスを倒して次を解放する。
収集・育成・攻略・メタ進行のループが一周し、演出と音が乗り、オフラインで遊べる。

### フェーズ1（動く3D）
- 円形アリーナ（地面グリッド・外周ブロック・散乱する装飾）
- 自機の移動（加速・減速・向きの追従・壁でのクランプ）
- カメラ追従（進行方向の先読み・注視点の遅延・シェイク）
- 仮想スティック（触れた位置に出現）／ WASD・矢印キー
- 適応品質（高／中／低の自動切替。低ティアでは実影を簡易影に置換）
- 縦持ち補正（垂直FOVを広げて水平視界の潰れを抑える）

### フェーズ2（戦闘コア）
- **オートエイム＋オートファイア**（射程内の最寄り敵を選び、0.35秒張り付く）。
  狙う相手がいる間は移動と向きが独立し、敵を睨んだまま横に逃げられる
- **2種類の攻撃形式**：`melee_arc`（正面の扇を薙ぐ・範囲）と
  `projectile`（弾を飛ばす・貫通）。武器データの `attack.kind` で切り替わる
- **敵3種**：スライム（追尾）／ケイブバット（回り込み・飛行）／ブルート（重装甲）
- **一様空間ハッシュグリッド**による近傍検索。敵同士の押し出し（分離）つき
- ダメージ計算（属性相性・敵ごとの耐性/弱点・クリティカル・ノックバック）
- 時間経過で密度と強さが上がる連続湧き。敵の種類も時間で解禁される
- 被弾（無敵時間つき）・死亡・死亡画面・再挑戦

### フェーズ3（レベル上げ）
- **経験値ジェム**：敵を倒した位置に落ち、近づくと吸い寄せられる。
  一度吸い寄せに入ったら範囲外に出ても追い続けるので取りこぼさない
- **ランレベル**：レベルアップでゲームが止まり、**スキル3択**を提示。
  上限に達したスキルは選択肢から外れる
- **スキル10種**：パッシブ7（HP・攻撃・速度・クリティカル・攻撃速度・回収範囲・被ダメ軽減）＋
  アクティブ3（ノヴァ・追尾雷・再生）。データを1件足すだけで増える
- **永続レベル**：ラン終了時に成績が永続経験値へ変換され、アカウントレベルが上がる。
  全ランに乗る恒久的なステータス補正になる（＝ラン跨ぎでキャラが育つ）
- **セーブ**：localStorage。バージョン管理・マイグレーション・バックアップ1世代・
  初期値とのディープマージ（旧セーブに新フィールドが自動で生える）。
  書き込みは遅延集約するが、ラン終了は即時保存する

### フェーズ4（ガチャ＆装備）
- **拠点（ホーム）**：出撃・ガチャ・装備の入口。所持通貨と記録を表示
- **ガチャ**：単発（💎100 / 🎟1）と10連（💎1000）。
  排出確率の表は `src/data/gacha.js` から生成しているので、
  データを書き換えれば表示も自動で追従する
- **天井**：ソフト50連から +5.0pt/連、ハード70連で確定。10連はSR以上を1つ保証。
  ピックアップすり抜け救済（外したら次のSSRは確定）
- **武器17種**（N5 / R5 / SR4 / SSR3）。データ追加だけで増える
- **特殊効果**：炎上（継続ダメージ）・凍結（減速）・爆発（範囲）。
  SSRほど強い効果を複数持つ
- **ダブり救済**：かけら→限界突破（+8%/段階・最大5）、強化粉→武器レベル（最大20）
- **演出**：予告 → リーチ → 排出 → 結果一覧。
  ★予告の色は結果と「弱い相関」に留めてある。白予告からSSRが出る逆転も、
  金予告がSRで止まる空振りも混ぜる（毎回確定演出だと期待が死ぬため）
- **課金要素なし**。通貨はプレイ報酬のみ

### フェーズ5（敵種・ボス・ステージ進行）
- **ステージ8種**。前のステージをクリアすると次が解放される
- **難度曲線**：敵HPはステージ番号の二次で伸びる（×1.00 → ×5.55）。
  ★ラン内のレベル上げだけでは追いつかないように設計してある。
  「もっと強い武器を引く／強化する」が必要になる＝ガチャと育成の動機になる
- **敵7種**：追尾・回り込み・重装甲に加えて
  **射撃**（距離を取って撃つ）・**突進**（溜め→直進）・**分裂**（倒すと欠片が残る）
- **ボス2種**：ゴアホーン（突進＋叩きつけ）／ヴォイドモウ（弾幕＋取り巻き召喚）。
  HPが減るとフェーズが進んで速く・手数が増える
- **予備動作を必ず見せる**：溜め＝黄、突進＝赤に本体が変色し、
  叩きつけは範囲を床に描く。予告のない攻撃はただの理不尽になるため
- **敵弾**は味方弾と同じプールを `hostile` フラグで共用し、赤く大きく描いて区別する
- **ボスは専用メッシュ**（雑魚は InstancedMesh、ボスは見せ場なので個別描画）
- 初回クリア報酬・ボスHPバー・クリア画面

### フェーズ6（メタ進行）
- **拠点強化8種**：最大HP・攻撃力・移動速度・クリティカル・回収範囲・被ダメ軽減・
  開始レベル・ガチャの強化粉効率。ジェムで買い、**すべてのランに永続で乗る**
- **実績18種**：撃破数・ボス討伐・攻略・育成・収集・強化。
  条件を満たした瞬間に達成し、報酬が自動で入る（受け取り操作なし）
- **キャラクター4種**：ヴァンガード（近接特化）／レンジャー（射撃・機動）／
  バルワーク（重装）／アーカニスト（一撃特化）。
  ★得手不得手をはっきり分けてある。近接攻撃力と射撃攻撃力が別々に乗るので、
  引いた武器の系統に合わせてキャラを選ぶ意味が生まれる
- **アンロック**：実績で解放される。
  「初討伐」→レンジャー ／「飛躍」（ランLv.20）→バルワーク ／
  「蒐集家」（SSR5本）→アーカニスト ／「深淵踏破」（ステージ8クリア）→**上級バナー「プライム」**。
  ★別々の遊び方に紐づけてある（同じ行動の延長で全部揃うと増やした意味が薄れるため）
- 達成トーストは同時表示を3件までに絞り、順番に流す
  （一度に5件達成すると画面が埋まって操作できなくなるため）

### フェーズ7（演出・音・PWA）
- **ダメージ数字**：WebGLの上に重ねた2Dキャンバスに描く。
  文字がぼやけず、draw call も増えない。クリティカルは大きく金色
- **火花・破片**：1つの `THREE.Points` に全粒子を詰めて **1 draw call**
- **衝撃波**：閃光・輪・光柱を InstancedMesh 3枚に畳む。爆発と叩きつけが共用する
- **見せ場の全画面演出**：SSR排出・ボス出現・ボス撃破・レベルアップ・ステージクリア
- **音は Web Audio API で合成**。音源ファイルは同梱しない（容量ゼロ・読み込み待ちゼロ）。
  レア度で排出音が変わり、リーチは鼓動のような連打で「溜め」を作る
- **共有テキスト＋コピーボタン**：到達ステージ・時間・撃破数・到達Lv・装備ビルドを1画面に
- **PWA**：`manifest.webmanifest` + Service Worker。
  three.js を含む全77ファイルをプリキャッシュし、**完全オフラインで遊べる**
- 音のオン/オフは拠点から切り替えでき、設定はセーブに残る

### ステージと背景の作り込み

- **舞台を12角形の建造物に**：床・縁（警戒帯＋胸壁＋発光する笠木）・
  外へ下る3段のテラス・12の頂点に立つ尖塔・12面の結界。
  **丸を使わない**。全部同じ12面で揃えて、一つの建造物として読ませる
- **ステージごとに景色が変わる**（`src/data/themes.js`）。
  色だけでなく**装飾の形・遠景の輪郭・霧の濃さ・光の色**まで差し替わる。
  崩れた闘技場／砕けた回廊／獣の巣／腐食の沼／雷鳴の尖塔／灰の平原／虚無の縁／深淵の顎
- **甲板は3枚重ね**：タイル（装甲板・六角ボルト・グリーブル）＋
  繰り返さない汚れ（ムラ・ひび・焼け跡・周辺減光）＋見取り図（外周リング・主線・紋章）
- **結界の外に遠景の塔**（`InstancedMesh` 1 draw call）と、空へ焼いた地平のシルエット
- **漂う粒子**（`Points` 1 draw call）。止まった空気は書き割りに見える
- **拠点では見せカメラ**に切り替え、舞台をゆっくり回して見せる。
  拠点とステージ選択の背景を透かしてあるので、選んだステージがその場で背景になる

### ガチャ確率の監査（単発20万回の実測）

| レア | 表示 | 実測 | 判定 |
|---|---|---|---|
| N | 53.0% | 52.78% | OK |
| R | 32.0% | 31.90% | OK |
| SR | 11.0% | 10.83% | OK |
| SSR | 4.0% | **4.49%** | OK（天井ぶん上振れするのが正しい） |

> 天井があるぶんSSRは表示確率より必ず高く出る。そして増えた確率質量は
> 下位レアから元の比率どおりに差し引かれるので、N/R/SR を表示確率とそのまま比べると
> 正常なのに低く出る。監査は**実測のSSR率を踏まえた期待値**と比較している
> （N 期待52.73%→実測52.78% / R 31.84%→31.90% / SR 10.94%→10.83%）。

上級バナー「プライム」（N除外）も、配り直した実効確率と実測が一致することを確認済み
（R 71.1%→71.21% / SR 24.4%→24.30% / SSR 4.5%→4.49% / N 0件）。

SSRの実効排出間隔は平均22.3回・最悪61回で、ハード天井70回を超えない。
10連保証は3,000回試行で保証割れゼロ。
`npm run gacha-audit` でいつでも再検証できる（確率表を編集したら必ず流すこと）。

## 起動方法

ES Modules と Service Worker はブラウザ仕様上 `file://` から動かないため、
**ローカルHTTPサーバ経由で開く必要がある**。

```bash
# いずれか
python3 -m http.server 8080
npx serve -l 8080
```

→ ブラウザで `http://localhost:8080` を開く。

### 開発ツール（ゲーム本体には含まれない）

ブラウザ実機での回帰確認用。**ゲームの配信物は three.js 以外に依存しない。**
`package.json` の devDependencies（Playwright）はこのツール専用。

```bash
npm install          # Playwright のみ
npm run serve        # 別ターミナルで起動しておく
npm run data-check   # データの矛盾を洗う（ブラウザ不要・数百ms）
npm run save-check   # 旧・壊れ・改竄セーブを流して互換性を確認（ブラウザ不要）
npm run smoke        # 起動・移動・壁・draw call・HUD・コンソール汚染を3ビューポートで確認
npm run perf         # JSフレームコストとループ内アロケーションを計測
npm run gacha-audit  # 排出確率・天井・10連保証を大量試行で検証
npm run pwa          # Service Worker登録 → 回線切断 → 本当にオフラインで遊べるか
npm run build        # 単一HTMLに畳む（dist/dopa-arena.html）
npm run single       # 畳んだ1ファイルを実ブラウザで起動・操作・保存まで確認
npm run check        # 上を全部まとめて実行
```

**単一HTMLビルド（`npm run build`）**

`tools/build-single.mjs` が ES Modules 一式（three.js 含む73ファイル）を1つの
`<script type="module">` に畳んで `dist/dopa-arena.html` を出す。約1.25MB。
**HTTPサーバを立てられない場所で配りたいとき**に使う。開発は普段どおり素のモジュールで行う。

各モジュールを IIFE で包み、`import` を親スコープからの分割代入に、`export` を戻り値の
オブジェクトに書き換える。スコープが分かれるので名前衝突は起きない。

> ★**解釈できない書き方に出会ったら必ず落とす。** 黙って読み飛ばすと、
> 「構文は通るが一部だけ死んでいる」バンドルが出る。実際にこれで2回騙されかけた。
>
> - minify 済みの three.js は `import{A as e,...}from"..."` と**空白が無い**。
>   `import\s+` にすると一致せず、剥がし残しに気付かないまま出力されていた
> - three.js は `export{...}from"./three.core.min.js"`（再エクスポート）を使う。
>   これを知らずに `export{...}` だけ剥がすと `from"..."` が文の途中に取り残される
>
> 対策として、畳んだJSを `node:vm` の `Script` で**構文解析してから**書き出す。
> 連番IDの重複バグ（`mods.size` から採番していて依存を先にたどる間に衝突）も
> これが見つけた。

`npm run single` は出力を実ブラウザで開き、起動・移動・撃破・ガチャ・localStorage 保存まで
通す。**構文が通るだけでは足りない**（評価順が狂うと参照だけ undefined になり静かに死ぬ）。
テスト用サーバは本体1ファイル以外を404にして、「実は外部ファイルを読んでいた」も暴く。

**データの自己検査（`npm run data-check`）**

このゲームは「データを1件足すだけで増える」設計なので、壊れ方もデータの矛盾に
集中する。存在しない敵IDを湧かせる、形の名前を打ち間違える、未実装の効果IDを書く、
レアリティと強さが逆転する——**どれも実際に遊ぶまで気づけない**。
`src/data/validate.js` が機械的に潰す。起動時にも走るので、
コンソールに出れば smoke の「コンソールがクリーン」が落ちる。

主な不変条件：

| 種類 | 見ているもの |
|---|---|
| 参照整合 | ステージが湧かせる敵・分裂/召喚の相手・ボス・目玉武器・解放フラグが実在するか |
| 列挙値 | レアリティ／属性／attack.kind／効果ID／スキル種別が実装済みか |
| 数値 | HPや攻撃力が0以下でないか、waveの時刻が昇順でステージ長の中か |
| 解禁の鎖 | ステージの `unlock` が前の面を指しているか（1本でも切れると先に進めない） |
| ボス | 全員が専用の形を持つか、ステージ間で使い回していないか |
| 強さの単調性 | **同じ攻撃種別の中で**、下のレアリティの方が強い武器が無いか |
| 危険信号 | 敵弾が寒色になっていないか（緑・水色は味方側の色） |

> ★**強さの比較は攻撃種別ごとに行う。** 近接は範囲内の全員に当たる（pierce 99）ので、
> 射撃と同じ物差しで比べると射撃が必ず負け、意味のない警告が出続ける。
> また単発火力ではなく「1振りで何体に当たるか」まで含めて測る（群れが相手なので）。

> ★層をまたぐ照合（データが書いた形の名前に実体があるか）は
> `tools/data-check.mjs` が受け持つ。`data/` は他の層に依存しない決まりなので、
> データ側には置けない。

> `npm run pwa` は `sw.js` のプリキャッシュ一覧と実ファイルを機械的に突き合わせる。
> ファイルを足して登録を忘れると「オンラインでは動くがオフラインだけ壊れる」という
> 原因の判りにくい事故になるため。
>
> ★検証は**実時間ではなくゲーム内時間で待つ**。
> ヘッドレスはソフトウェア描画なので、機械の負荷次第で実時間あたりに進む
> ゲーム内時間が変わり、実時間で待つと検証が不安定になる。

**ヒープ計測で自分を騙さないための決めごと**（`npm run perf`）

1. **`gc()` は2回呼ぶ。** 1回では回収しきれず、残りが計測窓の中で片付いたり
   片付かなかったりする。実際これで「1.5MB増えた」と誤検出し、
   各系統を個別に測ると全部0だった
2. **計測の直前に `await` しない。** event loop へ戻すとページ自身の
   `requestAnimationFrame` ループが走り、その描画ぶんが窓に紛れ込む（+3MB）
3. **描画統計は実際に1フレーム描いてから読む。** 描かずに読むと0件になり、
   「0件だから予算内」という無意味な合格になる。
   0件そのものを失敗として検出するようにしてある

## セーブデータ構造

- **保存先**：`localStorage`
- **キー**：`dopa_arena_save`（バックアップ：`dopa_arena_save_backup`。1世代だけ残す）
- **バージョン管理**：`v` フィールド。`MIGRATIONS` を段階適用して前進させる。
- **フィールド追加**：`INITIAL_SAVE` に足すだけでよい。読み込み時に初期値とディープマージするので、
  旧セーブにも自動で生える。`SAVE_VERSION` を上げるのは「形を変える」ときだけ。
- **破損時**：バックアップ→初期値の順にフォールバックし、ゲームは続行する。
- **保存できない環境**（プライベートモード・容量超過）でもゲームは止めない。

### 層の分け方

| ファイル | 責務 |
|---|---|
| `src/save/schema.js` | 形の定義（`INITIAL_SAVE`）と `MIGRATIONS` |
| `src/save/migrate.js` | **文字列 → 遊べる状態**。DOM に触れない純粋関数だけ |
| `src/save/SaveManager.js` | `localStorage` の入出力とデバウンスだけ |

★変換を `migrate.js` に切り出しているのは、**ブラウザ無しでテストするため**。
`tools/save-check.mjs` が古い・壊れた・改竄されたセーブを直接流して検証する。

### 読み込み時に必ずやること

セーブは「静かに壊れる」場所である。読めてしまうので気づかず、
数日後に「ガチャの天井が来ない」「キャラが選べない」という形で出る。
そこで読み込みは3段構えにしてある。

1. **マイグレーション**（`runMigrations`）— `v` を1つずつ前進させる。
   ★移行関数が**歯抜けでも止まらない**。`MIGRATIONS[2]` が無く `[3]` だけある場合でも
   2 を素通りして 3 を必ず適用する（＝フィールド追加だけの版を間に挟める）。
   移行関数が `v` を書き忘れても呼び出し側が前進させるので、無限ループしない。
2. **ディープマージ** — 足りないフィールドを `INITIAL_SAVE` から埋める。
   `__proto__` / `constructor` / `prototype` は踏まない（プロトタイプが差し替わると
   以後その枝の挙動が説明できなくなる）。深さも12段で切る。
3. **サニタイズ**（`sanitize`）— 型・範囲・参照先を正す。

| 直すもの | 例 |
|---|---|
| 型 | `gems: "abc"` / `null` / `NaN` / `Infinity` → 既定値 |
| 範囲 | 拠点強化が `max` 超え、天井カウンタが 99999、音量が 99 |
| 消えたコンテンツ | 削除した武器ID・実績ID・解放フラグ・ステージIDを落とす |
| 壊れる参照 | 存在しない／未解放のキャラ、所持していない武器の装備 → 既定へ |
| 肥大化 | ガチャ履歴を直近50件に切り詰める |

★**時刻の上限とカウンタの上限は別にする。** 同じ 1e12 で丸めると現在時刻
（1.7e12）が過去に飛ぶ。取得日時が全部同じになって並び順が壊れた。

### 新しいビルドのセーブを古いビルドが読んだとき

Service Worker が古いビルドを返す、端末を戻す、といった経路で起きる。
このとき `v > SAVE_VERSION` になる。

★**知らないIDは消さない。** こちらが知らないだけの武器や実績を消すと、
新しいビルドに戻った時に進行が失われる。参照側はすべてマスタから引くので、
知らないIDが所持データに混ざっていても実害は無い。
ただし**描画が落ちる参照**（存在しないキャラID）だけは、この場合も既定に戻す。

### セーブの形を変えるとき

1. `SAVE_VERSION` を上げ、`MIGRATIONS[新バージョン]` に変換関数を足す
2. `tools/save-check.mjs` の `OLD_SAVES` に**その版の実物**を1件足す
3. `npm run save-check`

★2 を飛ばさないこと。「昔のセーブが読めるか」は実物を通す以外に確かめようがない。

## パフォーマンス指針

これに反する実装は入れない。

| 指標 | 目標 |
|---|---|
| フレーム時間 | 16.6ms 以下（JS 4ms / 描画 8ms） |
| draw call | 100 以下 |
| 三角形数 | 60,000 以下 |
| 同時敵数 | 高200 / 中120 / 低70 |
| フレーム内アロケーション | **0** |

**守るべきルール**

1. **ゲームループ内で `new` しない。** `Vector3` / `Matrix4` はモジュールスコープで使い回す。
2. **大量オブジェクトは `InstancedMesh`。** アーキタイプごとに1 draw call。
   被弾フラッシュは `instanceColor` で表現し、マテリアルを増やさない。
3. **プールから取り、プールに返す。** 起動時に敵300/弾400/ピックアップ300/VFX64を確保。
4. **ライトは2つまで**（`DirectionalLight` + `HemisphereLight`）。点光源は使わない。
5. **ポストプロセス不使用。** ブルームは `emissive` と加算スプライトで偽装する。
6. **`sqrt` を使わない距離判定。** 距離の二乗で比較する。
7. **HUDは変化時のみ更新。** 毎フレームの `innerHTML` は禁止。
8. **重い処理は間引く。** 敵AIは4フレームに1回（インデックスで分散）、分離は2フレームに1回。
9. **敵1体の三角形は200まで。** 敵は最大150体、しかも影のパスでもう一度描かれるので、
   1体あたりの三角形が**そのまま2倍で効いてくる**。形を足したら
   `countEnemyTriangles()`（`src/scene/enemyShapes.js`）で数を見て、`npm run perf` の総数を確認する。
10. **毎フレーム走る関数からオブジェクトを返さない。** 「小さいから大丈夫」は効かない。
   敵AIの補助関数が1体1回の呼び出しでオブジェクトを1つ返していただけで、
   敵150体では毎秒約2000個になっていた。返り値はモジュールスコープの使い回しに書き込む。
11. **手続きテクスチャは低周波を小さく作って拡大する。** 1024x1024 を1画素ずつ
   ノイズで埋めると270msかかり、ステージを選ぶたびに画面が固まる。
   1/4で作って `drawImage` で伸ばせば見た目は変わらず20ms程度。
   輪郭が要るもの（ひび・線）だけ拡大後に原寸で描く。
12. **同じ形を何十個も置くなら合成ではなく `InstancedMesh`。**
   遠景の塔90本をジオメトリ合成で作ると、ステージ切替のたびに数百ms固まる。
   形は1つでよく、幅と高さの比を変えるだけで輪郭は十分ばらける。

品質は `src/scene/Quality.js` が直近90フレームの中央値から自動で高/中/低を切り替える
（DPR・影・パーティクル量・敵上限を段階変更）。設定画面から手動固定も可能。

## 見た目の作り方

画像ファイルは1枚も同梱していない。**テクスチャは全てキャンバスに手続きで描いている**
（`src/scene/textures.js`）。容量ゼロ・読み込み待ちゼロで、色や粗さをコードで調整できる。

### ポストプロセスを使わない代わりにやっていること

全画面のブルームやSSAOはモバイルで確実に重くなるので入れていない。
代わりに次の3つで質感を作っている。

**1. リムライト（輪郭光）** — `src/scene/materials.js` の `withRim()`

標準マテリアルのシェーダに数行だけ差し込み、視線に対して斜めを向いた面を光らせる。
暗い床の上で形が読めるかどうかは、ほぼこれで決まる。

> ★**曲面には効くが、平面には向かない。**
> 箱の側面はひとつの面が丸ごと同じ角度なので、面全体が白く飛ぶ。
> 特にカメラのすぐ手前に来ると巨大な白い板になって画面を壊す。
> 形ごとに強さを変えること（球 0.55 / 箱 0.22 程度）。

**2. 加算合成の光の板** — ブルームの代用

敵・弾・経験値ジェム・自機の足元に、中心が明るく外へ滲む板を重ねる。
本体は暗く落とし、**鮮やかな色は光の輪が受け持つ**。
本体まで明るいと「色つきの積み木」に見えて、暗い舞台から浮いてしまう。

> ★これは塗り面積（フィルレート）を食う。ヘッドレスの計測には出ないが実機のGPUでは効くので、
> 敵の光の輪は低品質ティアで丸ごと消している。

**3. 明暗差** — 環境光を落として、暗い床と光る敵の対比で見せる

`HemisphereLight` を強くしすぎると Lambert の出力が1を超えて色が白へ寄る。
夜のアリーナなので environment は控えめ（1.35）にしてある。

### 配色は「役割」で決める（設定画に合わせた統一）

キャラクター設定画（チビ体型・黒レザー・深紅の裏地・金の装飾・刀）を基準に、
**自機・敵・武器を同じ言語で揃えている**。

| | 体 | 光る色 | 差し色 |
|---|---|---|---|
| 自機 | 黒レザー | **金白（固定）** | 深紅の裏地・金の金具 |
| 敵 | 黒い装甲 | **深紅・琥珀・翠・紫の発光核** | 骨の角 |
| 武器 | 黒い柄 | 明るい刃と刃文 | 深紅の柄巻き・金の鍔 |

> ★**自機の足元の光は、キャラを変えても固定する。**
> 最初これをキャラのアクセント色にしていたら、深紅のキャラで
> 敵の発光核と同じ色になり、乱戦で自機を見失った。
> あれは個性ではなく「自分がどこにいるか」を伝える計器。

> ★**暗い衣装にできたのは、床を輝度38まで上げた後だから。**
> 床が真っ黒だった頃に同じ配色をやると、黒い自機が床に溶ける。
> 実際、以前の自機がほぼ白いカプセルだったのはそれが理由。順番は逆にできない。

> ★見下ろし視点で見えるのは**頭の上と肩の上面だけ**。
> 胸や腰をいくら作り込んでも画面には出ない。
> 金は肩と襟に通し、髪は毛先を明るくする。ここが自機の識別子になる。

### 1体の中の塗り分けは頂点カラーで持つ

黒い装甲・深紅の核・骨の角・金具を素直にマテリアルで分けると、
**1体で4〜5 draw call** になる。`mergeParts()` は part ごとの `color` を
頂点カラーとして焼き込むので、1体を1〜2メッシュに収められる。

- `mul` を 2 前後にすると、`MeshLambertMaterial` のままでも「発光する核」に見える
  （頂点カラーは 0..1 に縛られない）。emissive のためだけにマテリアルを分けずに済む
- 敵の `instanceColor` は**被弾フラッシュ専用**にした。平常時は白（素通し）で、
  フラッシュ時だけ 1 を超える値へ持ち上げて白飛びさせる

### 危険信号の色は譲らない

| | 色 | 形 |
|---|---|---|
| 自機の足元・斬撃 | **金白（固定）** | — |
| 自機の弾 | 属性そのままの色 | 滑らかな流線 |
| 敵の弾 | **必ず暖色**（赤・橙・琥珀・赤紫） | 四角錐の棘・1.5倍 |
| 敵の体 | 黒い装甲＋深紅の発光核 | — |
| 拾い物 | 翠 | — |

> ★**氷や雷の敵弾を水色にしてはいけない。** この作品では寒色＝味方側の信号で、
> 敵弾を水色にした瞬間「避けるべき物」に見えなくなる。
> 属性の違いは色ではなく形と大きさで伝える。
> `validateData()` が「赤が最大チャネルの7割未満」「緑が支配的」を検出する。

> ★色だけで分けないこと。自機弾と敵弾は**形から違える**（流線と棘）。
> 乱戦で背景に紛れたときや、色覚特性のある人には色だけでは区別が付かない。

### 技は必ず床に描く

判定とダメージだけで**画に何も出ない攻撃**は、避け方を体で覚えられない。
ボスの叩きつけは長らくこれだった（溜めの予告だけあって、着弾に何も無かった）。

`src/scene/vfx/Shockwave.js` が3層で1発を描く。

1. **閃光**（塗りつぶしの円・0.2秒）… 輪だけだと「線が広がった」で終わる
2. **輪**（外側と内側の2本）… 外側の最終半径は**実際の当たり判定と同じ値**
3. **光柱**（雷属性のみ）… 上から降ってくる

> ★**描く範囲は判定と必ず一致させる。** 見た目が判定より小さいと
> 「当たっていないのに死ぬ」、大きいと「当たったのに平気」になる。
> smoke が数値で突き合わせている。

> ★輪も閃光も加算合成。**色は1を超える値で入れる**（×2.4前後）。
> 素の色のままだと、明るくなった床の上では見えない。

> ★輪1本ごとに Mesh を作らない。InstancedMesh 3枚（輪・閃光・光柱）に畳む。
> 溢れたら一番古いものを潰して出し続ける（詰まって出なくなるより良い）。

### ボスの迫力は「高さ」で作る（幅ではない）

見下ろし視点で映るのはボスの上半分だけ。効くのは次の4つ。

1. **上面に情報を置く。** 肩当て・背の棘・角の張り出し・発光核を上から読めるように。
   腹や脚をいくら作っても画面には出ない
2. **一枚板にしない。** 装甲を重ねてズラすと、同じ体積でも重く見える
3. **前傾させる。** 垂直に立たせると置物になる。少し前へ倒すだけで「来る」
4. **横へ張り出させる。** 角・翼・肩で幅を稼ぐと実寸以上に大きく見える

> ★**当たり判定に合わせる基準は「胴の幅」にすること（`userData.hitHalf`）。**
> 境界箱の最大値に合わせると、角や翼まで含めてしまい、
> **派手な形ほど全体が縮む**。翼を付けた雷龍が自機と同じ大きさになった。
> 角の先や翼端は判定の外へはみ出してよい。中身が痩せる方が問題。

> ★**とぐろは螺旋に置く。** 真上へ積むと蛇ではなく「箱を積んだ塔」になる。
> 節は必ず重ねること。間が空くと積み木に見える。

> ★ボスは平面（箱）主体なので、リムライトを強く掛けると面がまるごと白飛びして
> 黒い装甲が薄茶色の塊に見える。鋭く弱くする（power 4.4 / strength 0.26）。

> ★撮って確認するときは `state` を `dead` にして update() を止めること。
> 自機の攻撃が当たると被弾フラッシュで全身が染まり、素の配色が確認できない。

### 形で語らせる（シルエット）

プリミティブを1つ置いただけの敵は「色つきの図形」にしか見えない。
`src/scene/geometry.js` で複数のプリミティブを合成し、**1つのジオメトリに焼き込んでいる**。
コウモリには翼、重装には肩当て、突進体には角、というように輪郭で種類が判るようにした。
武器も11種すべて別の形を持たせてある（引いた武器が違って見えないと、ガチャの意味が半分になる）。

合成しても `InstancedMesh` は1つのままなので **draw call は増えない**。増えるのは頂点数だけ。

> ★**三角形の予算は見た目の2倍で効く。**
> 敵は最大150体、そのうえ影のパスでもう一度描かれる。1体50三角形の差が
> 150体×2パスで15,000三角形になる。シルエットを付けた直後に予算6万を超えて
> 69,154まで膨らんだので、球の分割数を落として45,500に戻した。
> `countEnemyTriangles()` が1体あたりの内訳を返すので、形を足したら必ず見ること。

> ★three の `BufferGeometryUtils` は examples 側にあり同梱していない。
> 合成に必要な最小限（インデックスを剥がしての連結）だけ `mergeParts()` として自前で持っている。

### 見えない場所は作り込めない（そして拠点で見せる）

俯角62度のゲームカメラでは、**地面は約26m先で画面の上端に消える**。
アリーナの半径は34mなので、戦っている間は外周も尖塔も遠景も画面に入らない。
角に少し覗くだけ。

> ★これを知らずに外周を作り込むと、**一度も見えないものを作ることになる。**
> 実際、舞台の縁・段・尖塔・遠景の塔を作った直後の画面は、
> 「ただの床」のままだった。

対策は2つ。

1. **戦闘中に効くのは床と場内の構造物だけ**と割り切り、そこへ厚みを寄せる
2. **拠点では見せカメラに切り替える**（`CameraRig.showcase()`）。
   引いてゆっくり回し、ステージ選択で選んだ景色がそのまま背景に出る。
   拠点とステージ選択の画面だけ背景を透かしている（`#home, #stages`）

カメラの俯角そのものを浅くする案は捨てた。試したが、外周が少し見える代わりに
自機が小さく沈んで、**遊びやすさが確実に落ちた**。見た目のために操作性を削らない。

### 拠点は「見せ場」である（台座とショーケース）

同じ理屈が**キャラと武器**にも効く。俯角62度では自機は頭と肩しか映らない。
衣装も、髪型も、ガチャで引いた武器の形も、戦っている限り一度も見えない。
拠点に台座（`src/scene/Podium.js`）を立て、その上に立たせて見せる。

| 決めごと | 理由 |
|---|---|
| 台座はアリーナと同じ12角。テーマ色を引き継ぐ | 拠点だけ別世界の色になると、出撃した瞬間に同じ場所に見えない |
| 台座の素の色は `frame.base × 0.06〜0.10` | 半球光1.6＋指向光2.2で**3倍近い明るさが乗る**。0.2 を超えると「白い置き台」になり主役を食う |
| 台座のリムライトは `power 4.6 / strength 0.16` | 面の多い多角柱に強く掛けると外周が一斉に白飛びし、丸い発光塊になる |
| 低く広くしない（高さ0.97 / 天面半径1.00） | 低くて広いと「皿」に見え、主役が皿に乗った置物になる |
| 縁の飾りは板を放射状に。丸い柱を立てない | 角があるほうがシルエットが締まる。**まるっぽい台座は却下** |
| 板は本体の**外**へ出す | 中に埋めると先端の金だけが浮き、「縁に金塊が散っている」画になる |
| 足元の計器（オーラ・向きの三角・簡易影）は全部消す | あれは乱戦で自分を見失わないための表示。4ユニット四方の加算グローが台座ごと白く覆う |
| 武器は体の外へ振り出し、刃を立てる | 戦闘の提げ方（背後へ倒す）のままだと刀身が体に重なって形が読めない |

**構図**：被写体を画面の中央に置かない。中央はUIが占める。

- 横長 → キャラは左、UIは右（`.home-main { align-items: flex-end }`）
- 縦長 → キャラは上、UIは下（`.home-main { justify-content: flex-end }`）

★カメラを平行移動させると背景まで一緒にズレる。**注視点だけ**をカメラの右方向へ
逃がして、被写体を反対側へ追い出す（`CameraRig.showcase`）。
CSSとカメラは同じ想定で動かすこと。片方だけ変えるとキャラがボタンの裏に隠れる。

**幕（背景を暗くする膜）は文字のある側だけに掛ける。**
上下一律に掛けていた頃、キャラまで半分の明るさに落ちて真っ黒に見えていた。
横長は横方向のグラデーション、縦長は下半分だけ濃くする。

smoke が「画面高さの何%に映っているか」を数字で見張っている（20%未満で失敗）。
20%を下回ると遠くに人が立っている画になり、衣装も武器も読めない。

### 甲板は3枚重ね

| 層 | 中身 | 役割 |
|---|---|---|
| タイル | 装甲板・溝・六角ボルト・グリーブル・擦り傷 | 近くで見たときの密度 |
| 汚れ（繰り返さない） | 大きなムラ・ひび・引きずり傷・焼け跡・周辺減光 | **柄の繰り返しを殺す** |
| 見取り図（繰り返さない） | 外周の12角リング・12本の主線・中央の紋章 | 「設計された場所」に見せる |

> ★**繰り返す面にひびを描いてはいけない。**
> 同じひびが等間隔に並び、一目で「タイルを敷いた床」だと判る。
> ひびは繰り返さない層に持たせる。細部を足すより、
> **繰り返さない大きなムラを1枚重ねる方がずっと効く。**

> ★乗算合成（`MultiplyBlending`）は使っていない。この環境では暗くならず、
> 逆に床が真っ白に飛んだ。**黒い板のアルファで濃さを持たせれば `dst*(1-a)`**
> になり、掛け算と同じことを確実にできる。

### 明るさは数字で決める

「暗い舞台にすると格好いい」を突き詰めた結果、**床の画素の92%が輝度32未満**
（255段階）になっていた。パネルもボルトもひびも、描いてあるのに見えない。
これは雰囲気ではなく、ただの手抜きに見える。

やり方：スクリーンショットの床の帯を取り、平均輝度とヒストグラムを出して
**8テーマとも38前後に揃える**。目分量で色を触らない。

> ★**明度を上げるのにRGBを一律で掛けてはいけない。**
> チャンネルが255で頭打ちになって色相が壊れる。
> 深紅のはずの「深淵の顎」が蛍光ピンクになった。
> HSLに直して**色相と彩度は保ったまま明度だけ**動かすこと。
> ついでに、明るくするほど彩度は落とす（床が主役になってはいけない）。

> ★**ライトの色は画面の全部に乗る。** ここを濃く染めると、床をいくら
> 調整しても「単色フィルターを掛けた絵」から抜けられない。
> 環境光の色は白へ寄せ、色はリム（輪郭光）と発光物に持たせる。
> 構造物のリムだけ**補色**にすると、単色に見えないまま雰囲気は保てる
> （赤い巣に冷たい月光の縁、シアンの虚空に琥珀の縁）。

### そのほかの決めごと

- **床**：グリッドが主役にならないよう、線は細く暗くし、面の質感（雲状のムラ・擦り傷・
  パネルの面取り）で情報量を稼ぐ。発光する継ぎ目は別レイヤにして明滅させている
- **舞台の形**：**丸をやめて12角形にした。** 円い床・円柱・真円のリングは
  「仮組み」に見える。床・縁・段・尖塔・結界を全部12面で揃えると、
  ばらばらの飾りではなく一つの建造物として読める
- **背景**：単色だと「箱の中」に見える。グラデーション＋星＋星雲を張った球を
  カメラに追従させている。★半径は `camera.far` より内側にすること
  （外に置くと丸ごとクリップされて背景が真っ黒になる）
- **地平のシルエット**：空のテクスチャに焼く（ジオメトリ0）。
  ★**暗い色で塗るのではなく、空を一定量“暗く落とす”こと。**
  固定色で塗ると、明るいテーマでは画面に開いた黒い穴になる。
  ★描く高さも要注意。俯角62度では真の水平線(v=0.5)は一生映らないので、
  v≈0.70〜0.78 に置かないと「描いたのに出ない」
- **遠景の塔**：シルエットだけでは動いても景色が変わらず「絵」に見える。
  実体を置くと視差が出る。`InstancedMesh` で1 draw call、影は落とさない。
  ★近すぎ・高すぎると壁になって空を塞ぐ。頭が甲板の高さ前後で止まる遠さがよい
- **場内の構造物**：均等にばら撒くと「同じ物が等間隔に並んだ床」に見える。
  9カ所の塊に寄せ、16%だけ大きいものを混ぜる。粗密ができて、
  ついでに開けた場所ができて戦いやすくなる
- **装飾**：見下ろし視点では、高く細い物ほど画面端で大きく傾いて見え「倒れかけている」
  ように読める。低めの台座に留めている
- **自機**：足元に向きの三角を描く。見下ろしでは体の傾きより床の印の方が速く読める。
  体色はキャラで変えるが**暗くはしない**（白い体は床に溶けないことが目的）

## オフライン動作（PWA）

インストール後はネット接続なしで完全に動く。

- `sw.js` が three.js を含む同梱ファイル全77点をプリキャッシュする
- 取得方針は cache-first。オフラインで確実に動くことを最優先する
- 同一オリジンのみ扱う（そもそも外部への通信は一切しない）
- **リリースのたびに `sw.js` の `CACHE` のバージョンを上げること。**
  上げないと古いキャッシュが残り、更新が反映されない

`npm run pwa` が「Service Worker登録 → 回線切断 → 再読み込み → 実際に操作できるか」まで
本物のブラウザで確認する。
